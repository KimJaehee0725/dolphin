## Why

Codex에는 c90f27c 구버전만 설치되어 Claude와 기능이 달랐다. 사용자는 두 경로 통일과 최신 main 자동 반영, 원격 push를 요청했다.

## How

사용자 요청에 따라 research-history 스킬을 고정 SHA 대신 원격 main 최신 상태로 가져온다. build_image.sh가 runtime 설정을 로드한 뒤 원격 main을 조회하고 그 시점의 SHA를 동적 Docker 캐시 키로 넘긴다. 빌드 도중 main이 바뀌면 설치 전 명시적으로 실패한다. --print-history-revision은 runtime.env에 접근하기 전에 조회하고 종료한다.

Dockerfile은 main을 fetch해 upstream install.py로 Codex와 Claude 두 경로에 동일 payload를 설치한다. 실제 설치 SHA는 REVISION/INSTALLATION.json에 남긴다. 새 verifier가 두 manifest·전체 payload hash·기능·read-only --brief·BM25 fixture·파일 provenance CLI를 검사한다. COPY와 설치 계층은 plugin npm ci 다음, CMD 직전으로 이동해 최신 스킬만 바뀔 때 무관한 도구 설치 캐시가 유지되도록 했다.

스킬 원본 저장소는 /workspace/codes/track-research-history에 clone해 세 구현 에이전트와 교차 검토·독립 전방검증으로 수정했다. 전체111테스트가 성공했고 origin/main 41dd1e7d1d4138cb9f4727b9cce1a531da6a7654로 공개했다. 현재 컨테이너의 Codex/Claude도 해당 0.6.0 payload로 갱신해 verifier를 통과했다. Codex mount는 원자적 파일 갱신, Claude 일반 경로는 디렉터리 교체를 썼으며 이전 설치를 백업했다.

Dolphin 원래 작업트리에는 runtime.env.example 삭제와 private swap이 있어 이 변경은 별도 worktree에서 진행했다. runtime.env와 swap을 열거나 복사하지 않았다. 원격 main push 후 원래 main은 fast-forward하되 기존 사용자 변경은 보존한다.

## Risks / Follow-Ups

전체 CUDA 이미지는 빌드하지 않았다. 검증 범위는 수정한 설치 단계와 CLI/캐시 동작이다. 직접 docker build는 fresh cache key 또는 --no-cache가 필요하며 표준 build_image.sh가 동적 키를 자동 전달한다. main 최신 정책이므로 향후 upstream 변경에 따라 결과가 달라지고 실제 설치 SHA로 추적한다.
